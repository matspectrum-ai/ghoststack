# GhostStack

Projeto governado integralmente pelo gstack.

## Regra principal

Todo trabalho neste projeto DEVE passar pelo pipeline gstack:

/office-hours → /autoplan → /ship

## Skills obrigatórias

- /office-hours — definição de visão e problema
- /autoplan — plano executável com revisão automática
- /ship — implementação, revisão e publicação

## Skills complementares

- /plan-ceo-review
- /plan-eng-review
- /plan-design-review
- /review
- /qa
- /cso
- /browse
- /design-html
- /design-review
- /document-release
- /retro
- /investigate

## Proibido

- Criar código, design ou deploy fora do pipeline gstack
- Commits diretos sem passar por /ship
- Alterações manticas sem plano aprovado

## Workflow

1. Toda feature inicia em /office-hours
2. Plano aprovado vira PLAN.md em .planning/
3. Implementação via /autoplan
4. Revisão e QA antes do merge
5. /ship cuida do resto

## Stack

Sem restrições definidas. Quando o gstack estiver ativo, detalhes da stack técnica são definidos via skills.
